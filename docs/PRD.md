> 为长期写作建立一块属于自己的地方。本文档定义个人博客系统的目标、目标用户、功能范围、非功能指标与迭代节奏，作为后续界面设计与开发的依据。

---

## 01 项目背景与目标

作者希望拥有一个不受算法与广告打扰的自有阵地：内容以纯文本长期保存、可随时迁移；排版围绕长时间阅读优化；五年后回看，依然舒服，也依然找得到。

### 目标

| # | 目标 | 说明 |
| --- | --- | --- |
| 01 | 内容主权 | 文章以 Markdown 纯文本存储并纳入版本管理，不依赖任何平台，随时可整体迁移。 |
| 02 | 阅读体验优先 | 行宽、行高、字号与首屏速度围绕「长时间阅读」设计，而不是为了停留时长。 |
| 03 | 长期可检索 | 归档、标签与全文搜索并行，让旧文与新文拥有同等的被发现机会。 |
| 04 | 低维护成本 | 写作即发布；备份与依赖升级在内的日常维护，每月不超过一小时。 |

**本版不做：** 多作者协作 / 商业化广告位 / 社区与私信 / 会员与付费 / 站点后台与账号体系

---

## 02 目标用户

### 作者本人 · 主要用户

有稳定输出习惯，习惯用 Markdown 写作；对排版、性能与数据归属敏感，技术背景中等。

**核心诉求：** 发布足够快 · 写作环境足够安静 · 内容不会丢

### 读者 · 次要用户

多从搜索引擎或社交分享进入，移动端占比高，单次停留 2–5 分钟。

**核心诉求：** 首屏够快 · 正文够好读 · 能订阅后续更新

---

## 03 功能需求 · 前台

以下模块全部纳入同一版本实现，桌面端与移动端同步交付（不做分期）。

| # | 模块 | 说明 |
| --- | --- | --- |
| 1 | 首页 / 文章列表 | 置顶推荐卡片、纯文字文章列表（日期 + 标题 + 摘要 + 元信息，不用封面图）、分类分布、热门标签、订阅卡片、预计阅读时长。 |
| 2 | 文章详情 | 正文排版、目录锚点、代码高亮与一键复制、上下篇导航、第三方评论；不做分享按钮与打赏。 |
| 3 | 分类与标签 | 按主题浏览、标签聚合页，支持一个标签下的多分类交叉。 |
| 4 | 归档时间线 | 按年份倒序罗列全部文章，标注年份与篇数，支持按年份快速跳转。 |
| 5 | 全文搜索 | 标题与正文检索、关键词高亮；无结果时给出相关文章推荐。 |
| 6 | 关于我 | 个人简介、正在做的事、站点说明、联系方式、生活切片。 |
| 7 | 评论与订阅 | 评论接入 Giscus（读者以 GitHub 账号留言）；RSS 订阅入口；邮件订阅接入第三方邮件服务，首页侧栏常驻订阅卡片。 |
| 8 | 明暗主题 | 跟随系统或手动切换；主题选择在本地记忆。 |

## 04 写作与发布方式

站点不提供后台界面。写作与发布完全在仓库内完成：文章即 `content/posts/*.md`，git 是唯一数据源，推送即发布。原后台各模块的职责转由文件与成熟工具承担，站点自身不承载任何账号体系。

| # | 能力 | 承载方式 |
| --- | --- | --- |
| 1 | 文章写作 | 本地以 Markdown 撰写，frontmatter 记录标题 / 日期 / 标签 / 摘要 / 封面。 |
| 2 | 发布与回滚 | `git push` 触发自动构建发布；草稿即尚未提交，回滚即 `git revert`。 |
| 3 | 分类与标签 | 直接写在 frontmatter 字段中，由构建期生成聚合页，无需管理界面。 |
| 4 | 图片 | 放入 `public/images/` 并按文章分目录引用，引用关系随文章一并版本化。 |
| 5 | 评论 | 由第三方评论组件承载（如 Giscus），站点不保存读者账号与凭证。 |
| 6 | 站点设置 | 集中于单一配置文件（`site.config.ts`），随仓库版本化。 |
| 7 | 数据概览 | 接入第三方统计（如 Vercel Analytics），随一版实现一并接入。 |

**说明：** 站点不设登录、不设账号、不设数据库，因此不存在密码、会话与凭证泄露的风险；写作入口为本地编辑器与 Git 客户端，发布动作即一次推送。

## 05 非功能需求

| 维度 | 指标 | 说明 |
| --- | --- | --- |
| 性能 | 首屏 ≤ 1.5s | 4G 网络下首屏可交互；Lighthouse 性能分 ≥ 90。 |
| SEO | 可被完整收录 | 语义化标签、sitemap.xml、结构化数据、每篇文章独立 meta。 |
| 响应式 | 桌面 / 平板 / 移动 | 移动优先；断点 390 / 640 / 1024 / 1440，正文自动调节字号。移动端以 390 宽设计稿为准。 |
| 可访问性 | WCAG AA | 键盘可达；正文对比度 ≥ 4.5:1；所有图片具备 alt 描述。 |
| 安全 | 全站 HTTPS | 全站静态、无服务端接口，攻击面极小；Markdown 渲染做 XSS 过滤；依赖包定期安全审计。 |
| 可维护性 | 内容与代码分离 | 新增文章无需改动代码；依赖每季度升级一次。 |

## 06 信息架构

**前台页面**
· 首页 / 文章列表 · 文章详情 · 分类页 · 标签聚合页 · 归档时间线 · 搜索结果页 · 关于我 · 友情链接 · 404 页面

**写作与发布（非站点页面）**
· 本地 Markdown 编辑 · Git 提交与推送 · 第三方评论面板 · 第三方统计面板

**公共与系统**
· RSS 订阅 · sitemap.xml · 明暗主题切换 · 移动端导航（汉堡菜单展开） · 阅读进度条 · 站点地图页

**移动端适配（390 宽设计稿）**
· 首页 / 文章详情 / 归档时间线 / 关于我 四屏均有移动端稿；导航收敛为「标识 + 搜索 + 主题 + 菜单」，侧栏内容下沉到正文之后，页脚纵向堆叠

## 07 视觉与体验方向

整体气质：安静、克制、文字优先。界面不抢内容，动效只用于交代状态变化，色彩只保留一个强调色。

### 站点色板

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 纸底 | `#F5F0E6` | 页面底色 |
| 纸卡 | `#FAF6EE` | 卡片 / 分区底 |
| 纸片 | `#EDE5D5` | 标签片 / 输入底 |
| 纸边 | `#E5DDC5` | 描边与分割线 |
| 深纸边 | `#CFC4A8` | 强调分割线 / 置顶横线 |
| 墨黑 | `#2A2118` | 标题（暗色下为代码块底色） |
| 墨色 | `#3A2F22` | 正文 |
| 咖啡 | `#6B5B45` | 唯一强调色 / 次要文字 |
| 浅墨 | `#8A7C63` | 眉标、日期等辅助信息 |
| 淡墨 | `#A79B80` | 占位文字、最弱层级 |

明暗两套主题共用同一套语义令牌；暗色底 `#17130E` / 卡 `#201A13`，强调色提亮为 `#C9B48C`。

### 排版与规格

- 正文 16–18px，行高 1.75
- 阅读列宽 ≤ 680px，单行 50–65 字
- 标题使用思源宋体（Source Han Serif CN），正文使用思源黑体（Noto Sans SC）
- 眉标、编号与数字使用等宽字体（Geist Mono）
- 圆角 ≤ 4px，不使用渐变与投影
- 动效仅用于状态反馈，时长 150–250ms
- 移动端基准宽 390：正文 16px、行高 1.75；首页主标题 34px、文章标题 26px；导航高度 56px

## 08 实现范围（一版交付）

不做 MVP 分期，以下范围一次性实现、一次上线。颗粒度按「可独立验收」拆分，实现顺序只影响开发节奏，不影响交付范围。

| # | 交付块 | 内容 |
| --- | --- | --- |
| 1 | 工程骨架 | Next.js（App Router + TypeScript）仓库初始化、目录结构、构建脚本、README 与部署步骤。 |
| 2 | 设计系统 | 07 章色板与排版规格落为代码层样式令牌；明暗两套主题变量。 |
| 3 | 内容层 | `content/posts/*.md` 解析（frontmatter + 正文）、示例文章、图片目录约定。 |
| 4 | 公共组件 | 导航（含移动端菜单）、页脚、眉标、卡片、标签、分隔线、代码块（含复制）。 |
| 5 | 前台页面 · 桌面 | 首页、文章详情、归档时间线、关于我（以桌面 1440 设计稿为准）。 |
| 6 | 前台页面 · 移动 | 同四屏的移动端布局（以 390 设计稿为准），断点 640 / 1024 平滑过渡。 |
| 7 | 扩展页面 | 分类页、标签聚合页、搜索结果页、404 页面（与四屏同一套组件，不单独出设计稿）。 |
| 8 | SEO 与订阅 | sitemap.xml、RSS、结构化数据、每页独立 meta；Giscus 评论、邮件订阅（第三方服务）。 |
| 9 | 上线 | 构建校验、Lighthouse 体检、GitHub 推送、Vercel 接入与域名绑定指引。 |

**明确不做：** 站点后台与登录 · 账号体系 · 数据库 · 多作者 · 广告与付费

## 09 部署与托管

| 环节 | 方案 | 说明 |
| --- | --- | --- |
| 代码与内容 | GitHub 仓库 | 代码与 Markdown 文章同仓管理，git 为唯一数据源。 |
| 构建与发布 | Vercel | 连接仓库后自动构建，推送即上线；分支可生成临时预览地址。 |
| 访问地址 | 默认域名 + 自有域名 | 平台默认域名用于验收；正式使用建议绑定自有域名。 |
| 评论 | Giscus | 基于仓库 Discussions，站点无需自建服务端。 |
| 搜索 | 构建期 JSON 索引 | `next build` 产出 `/search-index.json`，浏览器端子串匹配。无服务端、无额外构建工具。（原计划 Pagefind，为减少一层外部工具依赖改为等效内置方案） |

### 技术约定（v1.3 定稿）

- **样式**：Tailwind CSS v4，设计令牌集中在 `app/globals.css`（`@theme` + CSS 变量），色板/字体/圆角改一处全站生效
- **静态导出**：`next.config.ts` 开启 `output: "export"`，构建产物为纯静态 `out/`，可托管于任意静态平台；不使用任何 Vercel 专有服务（KV / Blob / Edge Config / ISR / Server Actions / 运行时图片优化）
- **图片**：`public/images/`，提交前压好（宽 ≤ 1600px，WebP/JPEG，单张 ≤ 300 KB），正文引用一律写绝对路径 `/images/...`
- **目录约定**：文章 `content/posts/YYYY-MM-DD-slug.md`（URL 取 slug 段）；md 文件禁止放入 `public/`
- **站点地址**：RSS / sitemap / 分享链接的绝对地址由环境变量 `NEXT_PUBLIC_SITE_URL` 控制，部署时配置为正式域名

**托管限制：** Vercel 免费层（Hobby）条款限定个人、非商业用途。本项目的个人写作定位符合该条款；若后续出现广告、赞助等商业化行为，需升级付费方案或迁移至其他静态托管。静态产物无平台锁定，可随时整体迁移。
