复制的意思是「有两个同样的东西」。备份的意思是「其中一个坏了，另一个还能用」。听起来差不多，实际差得很远。

## 一、三个必须回答的问题

一套备份方案只要回答不了这三个问题，就等于没有：

1. 数据丢了的**最早发现时间**是多久？
2. 从发现到恢复，需要**多少人工步骤**？
3. 恢复出来的版本，**是多久之前的**？

很多人备份做得很勤，但第二个问题答不上来——真出事的时候，会卡在自己都忘了怎么恢复上。

## 二、3-2-1 的落地版

原则是：**3 份副本，2 种介质，1 份异地**。落到我这个博客上：

| 层 | 载体 | 覆盖什么 |
| --- | --- | --- |
| 1 | 本地磁盘 | 全部文件 |
| 2 | GitHub 仓库 | 文章与代码（不含图片大文件） |
| 3 | 对象存储 | 图片与构建产物 |

## 三、真正要练的是恢复

```bash
# 这一步才是备份方案的主体，别只写前面几条
git clone git@github.com:yourname/blog.git
pnpm install
pnpm build
```

**每半年真正跑一次恢复流程**，用一台干净的机器。跑不通，就等于没有备份。

三年后如果我还写博客，希望这篇能提醒我：备份的成本不在存储费，在你愿不愿意定期做一次诚实演练。
