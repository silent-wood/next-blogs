搬家的念头不是某一天突然冒出来的。它更像鞋里的一粒沙——你走了一整天，晚上脱下鞋才发现脚疼。

## 一、为什么要搬

最初写博客只是想留个记录。后来平台开始推荐、开始加入广告分成、开始改版。每一次变化都不大，但加起来，那块地方就不太像我的了。

> 我不是反对平台。我只是想在自己写下的东西和读它的人之间，不再隔着别的东西。

## 二、迁移那天发生了什么

我先把全部文章导成 Markdown，然后逐篇检查图片链接和代码块。结果是这样的：

- 11 篇的配图还托管在平台 CDN 上，需要重新下载
- 3 篇的代码缩进被前端样式吃掉了
- 2 篇的标题在导出时被截断

![迁移当天的截图](/images/posts/2026-09-12-blog-migration.svg)

整个过程比预想的顺利，核心命令只有三条：

```bash
git add content/posts
git commit -m "新文章：把博客搬回自己手里"
git push
```

## 三、数据放在哪里

现在这套结构很简单：Markdown 存在 Git 仓库里，图片放在仓库的 `public/images/`，站点本身是静态构建。没有数据库，也就没有需要备份的数据库。

## 四、代价与收获

代价说清楚：**失去了平台的流量**。以前发一篇文章多少会有人从推荐里点进来，现在不会了。

收获是，我重新开始为「写」本身而写。访问量从四位数掉到两位数，但每一条留言我都能认真回。
